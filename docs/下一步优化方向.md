# 下一步优化方向记录

> 本文档用于记录当前项目已经完成、还没有完成、可以继续增强、以及更大胆的后续方向。它不是 bug list，而是后续 P1.6 / P2 / P3 的能力池，便于比赛答辩、简历包装和后续开发取舍。

---

## 当前定位

当前系统已经从 P0 的“一键生成视频”升级为 P1.5 的“受控型 Agentic Workflow”：

- Node 保留为 API Gateway、Prisma/SQLite owner、文件上传、静态资源、任务状态、SSE 和 Python callback 入口。
- Python 是唯一 AI runtime，负责素材分析、视觉 caption、embedding、RAG、LangGraph Editing Agent、Seedance 视频生成、Retry、FFmpeg 拼接和后处理。
- 素材分析会生成 `caption / summary / tags / embeddingText / embeddingVectorJson / embeddingModel`。
- 智能分镜方案由 `LangGraph + RAG + LLM planning` 生成，并保存为 `EditingPlan`。
- 创建视频任务必须使用 `editingPlanId`，Shot 会从 EditingPlan 写入 `prompt / subtitle / bgmHint / sourceMaterialId / durationSec`。
- 单分镜重生成和重新拼接已经迁移到 Python。

当前还不是完全开放式 ReAct Agent，也不是完整的爆款视频方法论生产平台。后续优化可以围绕“参考视频库、剧本方法论、Agent 深度、评测闭环、生产化能力”展开。

## 方向一：优质视频库与参考视频拆解

- 当前状态：未完成。
- 优先级：高。
- 类型：比赛要求补齐 / 项目深度增强。

比赛要求里提到“找参考 -> 提炼方法论 -> 生产剧本”，并要求沉淀优质视频库、模板、剧本三类核心实体。当前项目只有素材库和剧本生成，还没有真正的优质视频库。

建议新增实体：

- `ReferenceVideo`：参考视频记录，支持站外链接、手动录入、自有视频上传。
- `ReferenceVideoAnalysis`：结构化拆解报告。
- `ScriptTemplate`：由多个参考视频沉淀出的剧本模板。
- `CreativeMethodology`：Hook 手法、卖点表达、分镜节奏、CTA 方式等方法论。

建议能力：

- 支持上传自有视频做拆解。
- 支持录入站外爆款视频 URL 或人工整理信息。
- 对参考视频生成结构化拆解报告：
  - Hook 手法。
  - 卖点表达。
  - 分镜结构。
  - 画面风格。
  - 字幕风格。
  - BGM / 节奏。
  - CTA 方式。
- 剧本生成时检索参考视频和模板，而不是只根据商品信息生成。

预期效果：

```text
参考视频库 -> 视频拆解报告 -> 方法论/模板 -> 商品剧本 -> EditingPlan -> 视频生成
```

这样可以真正对应比赛里的剧本模块要求，也能把系统从“商品驱动生成”升级为“参考案例驱动生成”。

## 方向二：剧本生成模块升级

- 当前状态：部分完成。
- 优先级：高。
- 类型：比赛要求补齐。

当前 `/scripts/generate` 的输入主要是商品标题、卖点、目标人群、使用场景和画幅。它可以生成结构化脚本，但没有使用参考视频库、模板库或方法论库。

建议升级为三种模式：

- 商品直出模式：保持当前能力，适合快速生成。
- 模板生成模式：选择某个剧本模板，按模板填充商品信息。
- 参考模仿模式：选择一个或多个参考视频拆解报告，提炼方法后生成新剧本。

建议剧本生成链路：

```text
商品信息
-> 检索 ReferenceVideoAnalysis / ScriptTemplate / CreativeMethodology
-> LLM 总结适合本商品的创意策略
-> 输出结构化 Script
-> 进入 EditingPlan 生成
```

预期效果：

- 剧本不再只是“普通大模型文案”，而是有参考来源和方法论依据。
- 答辩时可以解释“为什么这个 Hook 适合这个商品”。
- 后续可以积累类目级打法，例如耳机、护肤、家居、服饰分别沉淀不同模板。

## 方向三：EditingPlan 可视化与任务追溯

- 当前状态：基础追溯链路已完成，后续可继续增强历史对比和可视化。
- 优先级：高。
- 类型：核心链路可解释性 / Agent 决策可视化 / 用户体验补齐。

当前 `EditingPlan` 已经落库，并且视频任务会使用 `editingPlanId` 把分镜方案写入 `Shot`。但前端目前主要在生成当次短暂展示，刷新页面、进入任务详情页或查看历史任务时，用户很难看到完整的智能分镜方案，也不容易理解 Agent 为什么选择某个素材、某个分镜时长和某段提示词。

建议优先补齐两个能力：

1. 视频任务显式绑定 `editingPlanId`。（基础版已完成）
   - 在 `VideoTask` 表中增加 `editingPlanId` 字段。
   - 创建任务时保存本次使用的 `EditingPlan`。
   - 任务详情接口返回 `editingPlanId` 和对应方案摘要。
   - 后续单分镜重生成、重新拼接、失败追溯时，都能知道原始分镜方案来自哪一次 Agent 决策。

2. 前端展示智能分镜方案详情和历史方案。（任务详情基础版已完成，历史对比待增强）
   - 在脚本页或任务详情页展示最近一次 `EditingPlan`。
   - 展示整体策略、分镜 prompt、subtitle、bgmHint、durationSec、sourceMaterialId 和 reason。
   - 支持查看同一脚本下的历史分镜方案列表。
   - 展示每个分镜的素材来源和 RAG 命中依据，让用户看到“为什么选这张图/为什么不用素材”。
   - 在创建任务前允许用户确认当前方案，避免生成视频时不知道实际使用了哪套计划。

预期效果：

```text
Script -> EditingPlan 历史
       -> 用户查看/确认方案
       -> VideoTask 绑定 editingPlanId
       -> Shot 继承分镜字段
       -> TaskDetail 回看完整 Agent 决策依据
```

这样可以把“LLM 生成智能分镜方案”从一个后端中间结果，变成前端可见、可追溯、可解释的核心产品能力。它也能明显增强答辩时对 Agent/RAG 链路的说明力度。

## 方向四：Agent 深度增强

- 当前状态：部分完成。
- 优先级：中高。
- 类型：技术深度增强。

当前是受控型 Agentic Workflow，不是开放式 ReAct Agent。这个选择有工程合理性：视频生成成本高、耗时长、失败代价大，不能让 Agent 无限制试错。

可以继续增强，但建议保持受控。

### 推荐优先升级：Plan-and-Verify / Reflection-lite

如果只考虑比赛和当前系统稳定性，不建议把 Editing Agent 改成完全开放式 ReAct。当前业务链路比较固定，且视频生成成本高、耗时长、失败代价大，更适合采用受控的 Agentic Workflow。

推荐升级方向是：

```text
RAG 检索
-> LLM 生成 EditingPlan 草案
-> Critic / Verifier 检查
-> Repair 节点修正
-> 工程规则最终校验
-> EditingPlan 落库
```

这里的 Critic / Verifier 可以重点检查：

- `source_material_id` 是否来自 RAG 候选素材。
- 如果 LLM 明确返回 `source_material_id = null`，说明候选素材不适合该分镜，应尊重 null，不强行塞素材。
- 分镜 prompt 是否和素材 caption / summary 匹配。
- 是否出现商品没有提供的夸大卖点或绝对化表达。
- 分镜时长是否符合 Seedance 当前 4-12 秒限制。
- 字幕是否过长，是否遮挡商品主体。
- 多个分镜是否过度重复使用同一素材。

这个方向比直接做 ReAct 更适合当前比赛项目：它能体现多步规划、自我检查和幻觉规避，同时保持生成链路稳定、可解释、可复现。

后续可以把模型选择也纳入这一层：

| 任务 | 推荐模型选择 |
| ---- | ------------ |
| 脚本生成 | 中文表达稳定、成本较低的文本模型 |
| EditingPlan 规划 | 推理能力更强的文本模型 |
| Critic / Verifier | 低温度文本模型，重点做一致性和合规检查 |
| 素材 caption / 参考视频拆解 | 多模态模型；当前豆包视觉和文本可复用同一 endpoint |
| embedding | 专门 embedding 模型；当前优先通义千问 embedding |

提示词也建议从“只约束 JSON 格式”升级为“引导决策过程”：

```text
1. 判断每个分镜目标：Hook / 卖点展示 / 场景证明 / CTA。
2. 查看 RAG 候选素材，判断素材是否匹配。
3. 如果素材不匹配，返回 source_material_id = null，并说明原因。
4. 为每个分镜输出 prompt / subtitle / bgm_hint / duration_sec / source_material_id / reason。
5. 自检时长、素材 ID、卖点真实性、重复素材和合规风险。
```

可做方向：

- 增加内部 Tool Registry：
  - `search_materials`
  - `inspect_material`
  - `search_reference_videos`
  - `select_template`
  - `validate_duration`
  - `estimate_generation_risk`
- 在 Editing Graph 中加入有限 function calling：
  - 允许 LLM 在固定工具集合内选择工具。
  - 每次工具调用都有预算和 trace。
  - 不做无限 ReAct 循环。
- 增加 Planning / Critic 双阶段：
  - Planner 生成 EditingPlan。
  - Critic 检查素材匹配、卖点覆盖、时长、合规风险。
  - Repair 节点修正结果。

不建议现在直接做完全开放式 ReAct：

- 成本不可控。
- 视频 API 调用慢。
- 容易产生不可复现结果。
- 比赛演示更需要稳定链路。

预期效果：

```text
RAG Planning Agent -> Tool-Augmented Agent -> Planner/Critic/Repair Agent
```

这样比单纯说“用了 Agent”更有深度，也更符合真实工程。

## 方向五：ViMax 启发的视频 Agent 增强

- 当前状态：未完成。
- 优先级：中高。
- 类型：开源项目启发 / 视频生成链路深度增强。
- 灵感来源：HKUDS/ViMax 的 agentic video generation 思路。

ViMax 的价值不在于直接照搬代码，而在于它把视频生成拆成了更细的“导演式链路”：脚本理解、分镜设计、参考图选择、首尾帧描述、运动描述、一致性检查、片段生成和拼接。这个思路可以用于增强本项目的电商短视频 Agent 深度。

建议吸收三个方向：

1. 升级 `EditingPlan` schema，让分镜从“一个视频 prompt”升级为“镜头计划”。
   - 当前每个分镜主要包含 `prompt / subtitle / bgmHint / durationSec / sourceMaterialId / reason`。
   - 后续可以增加：
     - `firstFramePrompt`：首帧画面描述。
     - `lastFramePrompt`：尾帧画面描述。
     - `motionPrompt`：镜头运动和主体变化。
     - `cameraType`：固定、推近、跟拍、旋转、特写等。
     - `transitionHint`：分镜之间的转场建议。
     - `materialUsage`：素材在该分镜中的使用方式。
   - 这里不是放弃素材库，而是让 `sourceMaterialId` 成为镜头的视觉锚点：RAG 选出的商品图/素材图仍然传给视频模型，首帧、尾帧和运动描述用于约束这张素材应该如何进入场景、如何变化。

2. 新增 `MaterialSelectorAgent`，把素材选择从 EditingPlan 的附带字段升级为独立决策节点。
   - 当前系统已经会给分镜选择 `sourceMaterialId`，但这个选择过程还比较轻，主要发生在 Editing Graph 内部。
   - 后续可以独立出一个节点：
     ```text
     分镜目标
     + RAG 候选素材
     + 素材 caption / summary / tags / embedding 相似度
     + 已使用素材记录
     -> sourceMaterialId / materialUsage / reason / fallback
     ```
   - 这样可以解释“为什么这个分镜用这张图”，也能避免不同分镜重复选择同一张素材。
   - 如果没有合适素材，Agent 应明确返回空素材，回退到纯文本视频生成，而不是硬塞不相关图片。

3. 增加 `PlanCritic` 检查节点，先检查计划，再生成视频。
   - 这个节点不需要直接读取视频，优先检查生成前的 `EditingPlan`。
   - 可检查内容：
     - 分镜时长是否符合视频模型限制。
     - `sourceMaterialId` 是否存在。
     - 素材是否和分镜目标匹配。
     - 商品卖点是否覆盖完整。
     - 字幕是否过长。
     - 多个分镜是否过度重复。
     - prompt 是否存在夸张宣传、违规承诺或不适合电商投放的表达。
   - 后续可扩展为 `VideoCritic`：视频生成后抽关键帧，用视觉模型检查商品是否出现、字幕是否遮挡、画面是否符合分镜。

推荐落地顺序：

```text
MaterialSelectorAgent
-> EditingPlan schema 增强
-> PlanCritic / Repair 节点
-> 可选 VideoCritic 抽帧检查
```

预期效果：

- 智能分镜不再只是“LLM 生成几段 prompt”，而是更接近导演分镜。
- RAG 素材库从“找一张图”升级为“给镜头提供视觉锚点”。
- Agent 链路从单次规划升级为“选择素材 -> 规划镜头 -> 检查计划 -> 执行生成”。
- 答辩时可以说明项目借鉴了 ViMax 类 agentic video generation 的思想，但保留了电商业务场景的素材库、商品卖点和转化目标。

## 方向六：Memory 设计

- 当前状态：未做真正 Agent Memory。
- 优先级：中。
- 类型：长期体验增强。

当前系统已有业务持久化：

- Material 语义信息。
- EditingPlan。
- TaskTrace。
- MockMetric。

这些不是标准 Agent Memory。后续可以增加三类 memory：

- User Preference Memory：记录用户偏好的风格、语气、字幕密度、镜头节奏。
- Product Memory：同一商品历史生成过哪些脚本、分镜、视频，哪些版本效果更好。
- Creative Memory：沉淀某类商品常用 Hook、卖点表达和分镜模板。

建议实现方式：

- 短期先用 SQLite 表。
- 中期接入向量检索。
- 后期迁移到 PostgreSQL + pgvector。

预期效果：

- 第二次生成同类商品时能复用历史偏好。
- 可以回答“为什么这次推荐这个风格”。
- 为后续 SFT/RL 采集数据。

## 方向八：MCP / Function Calling / 工具协议

- 当前状态：未接入 MCP；已有代码级工具编排。
- 优先级：中。
- 类型：技术扩展方向。

当前工具调用由代码和 LangGraph 节点控制：

- caption provider。
- embedding provider。
- text provider。
- video provider。
- FFmpeg tools。
- callback client。
- retry agent。

没有 MCP 的原因：

- 当前工具集合固定。
- 工具都在项目内部。
- 直接函数调用更简单、更稳定、更好测。
- MCP 更适合多客户端、多 Agent 共享外部工具生态。

后续可以分三步增强：

1. 内部 Tool Registry。
2. LLM function calling 使用固定工具。
3. 把部分工具封装为 MCP server。

适合封装为 MCP tools 的能力：

- 查询素材库。
- 查询参考视频库。
- 查询 EditingPlan。
- 查询任务状态。
- 发起素材分析。
- 发起智能分镜方案生成。

预期效果：

- 支持外部 Agent / IDE / 自动化工具调用本项目能力。
- 能把项目包装成一个可复用的电商视频生成工具服务。

## 方向九：真实数据闭环与 A/B 测试

- 当前状态：未做真实投放数据，只有 mock analytics。
- 优先级：中。
- 类型：产品闭环增强。

当前数据看板是 mock，用于展示 CTR/CVR/完播率和 Agent 优化建议。后续可以接真实数据。

建议新增：

- `VideoVariant`：同一商品多个视频版本。
- `Experiment`：A/B 测试实验。
- `PerformanceMetric`：真实或导入的 CTR、CVR、完播率、收藏率、点击率。
- `CreativeFactor`：Hook、风格、字幕、BGM、CTA、素材类型等可分析因子。

能力：

- 多版本视频生成。
- 同商品 A/B 对比。
- 根据效果反推哪些创意因子有效。
- 自动推荐下一版优化方向。

预期效果：

```text
生成视频 -> 投放数据 -> 因子归因 -> Agent 优化建议 -> 下一版视频
```

这会让系统从“生成工具”升级为“增长优化工具”。

## 方向十：合规审核 Agent

- 当前状态：未做。
- 优先级：中。
- 类型：电商生产化必备。

电商带货视频需要避免：

- 夸大宣传。
- 绝对化用语。
- 医疗/功效违规。
- 平台禁词。
- 虚假价格承诺。
- 人脸、版权、素材授权风险。

建议新增：

- Compliance Agent。
- Prompt / subtitle / script 审核。
- EditingPlan 审核。
- 视频生成前阻断高风险内容。
- 生成合规修改建议。

预期效果：

- 让系统更接近真实商用平台。
- 答辩时能体现“生成质量 + 风险控制”。

## 方向十一：视频素材深度理解

- 当前状态：图片 caption 已做；视频素材拆解未做。
- 优先级：高。
- 类型：比赛要求补齐 / 素材理解增强。

当前视频素材只是普通文件，未做抽帧、镜头检测和结构化拆解。

建议新增：

- 视频抽帧。
- 关键帧 caption。
- 镜头切分。
- OCR 字幕提取。
- 音频节奏估计。
- 画面风格分析。

## 建议优先级

### 第一优先级：先让已有 Agent / RAG 能力可见、可追溯

这部分投入相对小，但能立刻解决“后端做了智能分镜，前端看不到完整决策依据”的问题，也能让答辩时更清楚地证明当前 Agent 链路不是空壳。

1. VideoTask 显式绑定 `editingPlanId`，打通任务与智能分镜方案的追溯关系。
2. 前端展示 `EditingPlan` 详情、历史方案、素材选择依据和 RAG 命中信息。
3. 任务详情页展示每个分镜的 `reason / sourceMaterialId / RAG 候选摘要 / trace`。

### 第二优先级：补齐比赛任务里的硬要求

这部分直接对应 Word 文档中“素材—剧本—创作”三大模块，尤其是当前缺口最大的“找参考 -> 提炼方法论 -> 生产剧本”和“视频素材多颗粒度理解”。

1. 优质视频库：新增 `ReferenceVideo`，支持手动录入站外爆款链接、上传自有参考视频、声明素材来源。
2. 参考视频拆解：新增 `ReferenceVideoAnalysis`，输出 Hook 手法、卖点、分镜、风格、字幕、BGM、CTA 等结构化报告。
3. 方法论和模板沉淀：新增 `ScriptTemplate / CreativeMethodology`，把一批参考视频归纳为策略和因子。
4. 剧本生成接入参考视频、模板和方法论，不再只根据商品信息直出。
5. 视频素材深度理解：对上传视频做抽帧、关键帧 caption、整体摘要、embedding 和基础切片信息。

### 第三优先级：增强 Agent 深度和视频生成控制力

这部分用于提升技术深度，适合在比赛硬要求补齐后继续做。重点不是堆 Agent 名词，而是让分镜规划、素材选择和计划检查更像真实视频生产链路。

1. Tool Registry。
2. Planner / Critic / Repair。
3. ViMax 启发的 `MaterialSelectorAgent`。
4. ViMax 启发的 `EditingPlan` 镜头计划 schema 增强。
5. ViMax 启发的 `PlanCritic` 检查节点。
6. Agent Eval Harness。
7. Memory 表设计。
8. 合规审核 Agent。

### 第四优先级：生产化与增长闭环

这部分更偏 P2/P3 加分项和工程化，不建议抢在比赛核心链路前面做。

1. 真实投放数据。
2. A/B 测试。
3. 向量库升级。
4. TTS / BGM。
5. 队列、Worker、对象存储、Docker。
6. CI/CD、压测和监控告警。
